<objective>
This plan closes CR-03 (01.1-VERIFICATION truth 8) in hex-publish.yml. Today the ancestry check resolves the tag name, while actions/checkout resolves an unqualified `ref:` as a branch first, so a branch named like the tag decides what gets built. The publish and smoke jobs also re-resolve the tag, and `mix hex.publish --yes` uploads a fresh tarball that nobody compares with the build's checksum.

The fix resolves the tag once, to a commit, before any code from the tag runs. It asserts that the checkout is that commit, checks ancestry on it, carries it to every later job, and requires the rebuilt tarball to match the build's checksum before publishing. It also makes the publish gates fail closed (01.1-REVIEW WR-01) and, because the check now runs before setup, closes the deferred WR-05 follow-up.

Purpose: REL-01's recovery path publishes only commits on main, and SEC-02's "published only after the prod-guard cases passed" holds for the commit that is actually uploaded.
Output: one modified workflow, one updated deferred list, and one merged `.github/` PR. Its guard, `test/contract/hex_publish_test.exs`, lands in Plan 01.1-05.
</objective>
