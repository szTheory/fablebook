<objective>
This plan closes the Phase 1 verification blocker CR-01 and its same-root-cause warning WR-03 in one PR that edits only contract tests. Phase 1's criterion-4 share for the atom ban is re-homed to Phase 01.1 (INT-20261029-01). ADR 0004 is a non-negotiable: no atoms from input, no runtime eval, no runtime code loading. Today a one-line `lib/` change of the form `apply(String, :to_atom, [input])` passes `mix ci` on both lanes, because the BEAM guard's ban sets list only the Erlang BIF names that a direct call is inlined to. This plan grows the ban sets so that every literal dispatch form, each enumerated runtime compile, load and eval path (including the compiler-internal tokenizer, parser and module-compile chain), and each enumerated atom-creating read, scan, parse or format function fails CI. It brings the Credo layer to parity and makes the `mix.exs` text scan non-vacuous (WR-02).

Purpose: SEC-01's static-ban share. Phase 5 still owns the StreamData atom-count property and the mutation-proven tests, and those (the atom-count property and the never-eval proof) are the backstop for runtime-computed dispatch. This plan widens D-23's atom and MFA tiers and narrows nothing, so it implements ADR 0004 rather than amending an owner-signed decision.
Output: one modified contract test, one modified Credo check, nine new negative fixtures, and one merged PR that touches no file in `lib/` or `.github/`.
</objective>
