## Boundaries and Verification

- Preserve all 177 current EX-107 matches per lane and identify only the nine table functions plus `asn1ct_check:check/2` and `asn1ct_gen:insert_once/2` as the selected slice (D15-01).
- Reuse the approved offline archive and existing evidence contracts; add no network fetch, dependency, second ledger, or audit platform (D15-03, D15-04, D15-06).
- Do not execute ASN.1 functions. Use static source and compiled-BEAM inspection with uncalled function bodies (D15-05).
- If a selected front is called from `lib/`, preserve inherited D-11's stop and report its exact caller; do not choose an allowlist or application refactor.
- Keep the existing Macro and wording checkpoints; do not close the aggregate, SEC-01, or Phase 2, and do not assign another phase ID under the one-phase owner exception (D15-07, D15-08).
- Run the focused core suite after core binding and the focused floor suite after floor binding; run full required core/floor delivery checks after integration. Reuse commands from `01.1.1.15-RESEARCH.md` and bind CI to the tested revision.

## Avoid

- Treating the 11 selected matches as the full EX-107 row.
- Treating fixed table names as proof that stored values cannot contain caller-created atoms.
- Attributing atoms created in caller code to `asn1ct_table`.
- Replacing the existing row authority, downloading sources during recurring tests, or changing application runtime behavior.
