## Summary

The current exact-lane EX-107 sets each contain 177 matched MFAs. The selected slice is the nine `asn1ct_table` functions, `asn1ct_check:check/2`, and `asn1ct_gen:insert_once/2`. Both lanes have the same selected set, 28 incoming edges to the table wrappers, and 17 distinct caller MFAs. The full row remains pending outside this bounded review. [Verified: `01.1.1.1-AUDIT-BUDGET.json`; `01.1.1.1-CURRENT-SIZING-CORE.jsonl.gz`; `01.1.1.1-CURRENT-SIZING-FLOOR.jsonl.gz`.]

The table wrappers do not convert table names into atoms: `asn1ct_table:new/1` passes the supplied atom to `ets:new/2`, the other operations use it as a process-dictionary key for existing ETS tables, and `delete/1` accepts an atom or a list. `asn1ct_gen:insert_once/2` forwards its table argument to `lookup/2` and `insert/2` without converting it. Direct callers use literal table names. [Verified: exact core/floor `asn1ct_table.erl:38-74` / `:36-72` and `asn1ct_gen.erl:1379-1385` / `:1366-1372`; file hashes are in the sizing artifact.]

The corrected caller trace shows two routes into `asn1ct_gen:insert_once/2`: `asn1ct_check:check_type/3` passes `parameterized_objects`; `asn1ct_check:insert_once/3` forwards its table argument, and its four source callsites use `inlined_objects` once and `parameterized_objects` three times. These are compiled literals on both lanes. The sizing note's former statement that the forwarded table was always `parameterized_objects` was incomplete; its source span and token count are now corrected.

**Do not turn that table-name result into a claim that all selected caller paths are safe.** `asn1ct_check:match_syntax_type/3` constructs `InlinedObjName` and a type `Name` with `list_to_atom`, then stores data containing those atoms under the fixed table names. This is a separate stored-value path. `asn1ct_check:check/2` reaches checking routines, so planning must trace whether the bounded entry path makes this atom creation relevant to its disposition. The table wrappers themselves do not create those atoms. No conclusion about the other 166 EX-107 matches follows from this finding. [Verified: exact `asn1ct_check.erl:1429,1435,1458,1461,1488` core and `:1425,1431,1454,1457,1484` floor; `check/2` table initialization and cleanup at core `:93-94,145,153` and floor `:89-90,141,149`.]

- Never call `asn1ct_table`, `asn1ct_check:check/2`, `asn1ct_gen:insert_once/2`, or the observed atom sinks as a test input.
- Do not remove or cap matches to make a test pass. Any row portion split or reclassified must retain a complete union back to EX-107 on each exact lane.

## Validation Architecture

- **Contract layer:** `test/contract/tier_sweep_test.exs` remains the authority for the complete EX-107 match union, the lossless 11-MFA sub-scope, lane-specific source citations, dispositions, and individual removal witnesses.
- **Source authority layer:** `test/support/sweep_evidence.ex` resolves only the checked-in offline archive and verifies the manifest, full archive digest, lane/path identity, bytes, SHA-256, and cited source lines. Core and floor source records are added in separate tasks so each lane is reviewed against its own bytes.
- **Guard layer:** `credo/checks/banned_calls.ex` and `test/contract/banned_calls_test.exs` verify only the active selected guard fronts. Use the existing Credo and `BeamWalker` probe helpers for direct, capture, and apply references; keep all audited calls in uncalled function bodies and never invoke them.
- **Focused commands:** `MIX_ENV=test bin/lane core test --warnings-as-errors test/contract/tier_sweep_test.exs test/contract/banned_calls_test.exs` and the same command with `floor` replace `core`.
- **Delivery commands:** core uses `MIX_ENV=test bin/lane core mix ci`; floor uses `bin/lane floor mix compile --warnings-as-errors`, `bin/lane floor mix compile --no-optional-deps --warnings-as-errors --force`, and `bin/lane floor test --warnings-as-errors --include prod_guard`, matching the existing CI workflow. Record the CI run URL against the tested revision.
- **Manual review boundary:** trace the table identifier independently from stored object values and decide whether `asn1ct_check:check/2` reaches the `list_to_atom` path; static source/BEAM checks cannot establish runtime atom-count behavior.
- **Sampling:** run the matching focused lane command after each lane-binding task, then the required full core/floor delivery checks after the integrated contract and guard task. Timing for this slice is not measured; Phase 01.1.1.14 measured about 417 seconds core and 320 seconds floor for focused contracts, so use actual intervals rather than assuming those are current runtimes.
