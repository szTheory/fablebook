## Decisions Made

- `Code.format_string!/1,2` and `Code.format_file!/1,2` are banned now. No lib/ code uses them, and ADR 0004 is a non-negotiable. A later need, such as formatting a scenario's source for display, adds an `@allowlist` entry through its own ADR.
- `:file.consult` and `:file.path_consult` stay allowed. They read trusted compiled term files, and Q13(a) may read the compiled `.app` file for discovery (T-01.1-06, accepted).
- `@allowlist` stays `[]`. `test/support/beam_walker.ex` is unchanged.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `:xmerl_scan` does not load under `mix test`**
- **Found during:** Task 3, in the "every MFA matcher names an existing function" test.
- **Issue:** The plan's verified fact says `:xmerl_scan` loads in `mix test`. It does not, because Mix prunes the code path to the project's declared applications. `Code.ensure_loaded?(:xmerl_scan)` returned false, and the test failed with "{:xmerl_scan, :_, :_} names a module that does not load".
- **Fix:** `Mix.ensure_application!(:xmerl)` at the start of that test. This public Mix API exists since Elixir 1.15, so it works on both lanes. The tier entry is unchanged, nothing is weakened, and `mix.exs` and the shipped application are untouched.
- **Files modified:** test/contract/banned_calls_test.exs
- **Verification:** 28 passed on both lanes, and the typo'd-matcher control still fails.
- **Committed in:** 5eebf21

**2. [Plan arithmetic] One Task 3 grep criterion prints 9, not 7**
