## Critical Issues

### CR-02: [BLOCKER] A successful partial Xref query is treated as a complete graph

**File:** `test/contract/tier_sweep_test.exs:3151-3161, 3198-3205`; parity check at `2769-2774`
**Issue:** `xref_query!/3` accepts any `{:ok, rows}` list, including an empty or truncated Xref `E` or `X` result. The independent parity check compares only discovered, inspected, and ingested app/module identities; it does not check the queried edge or export sets. Those query results feed the historical/full graphs and receipt directly. A successful but incomplete query can therefore omit callers or exports without an Xref error, and the receipt’s internally derived counts will agree with the incomplete graph.

**Fix:** Validate queried exports and edges against an independent per-BEAM export/edge inventory before using them, and add a controlled query seam with successful-empty and successful-truncated negative controls. Fail with the lane and omitted identities when the sets differ.

## Warnings

### WR-02: [WARNING] Pending caller chains omit caller arities

**File:** `test/contract/tier_sweep_test.exs:3125-3144` (receipt fixture: `4562`)
**Issue:** `pending_inventory_records/6` serializes each caller as `Module.function`, while `reach/3` stores parent nodes as `{module, function}` and discards arity. Erlang functions can share a name at different arities, so the emitted path cannot identify the exact caller MFA. The receipt fixture uses `probe.run/0`, but the producer cannot emit that form.

**Fix:** Preserve caller MFA arities through reachability parent tracking and serialize each chain element as `Module.function/arity`; have receipt validation require that form.

### WR-03: [WARNING] Boundary metric counts only explicit exclusion matches

**File:** `test/contract/tier_sweep_test.exs:2850-2852, 2900, 3015-3020, 3664-3677`
**Issue:** Receipt records labeled `boundary` are generated only for reached MFAs matching `@boundary_exclusions`. The existing boundary universe also includes barrier modules/functions, derived sink delegates, Erlang boundary functions, and the front of barriers. As a result, `boundary_matches` is not a count of the computed full-graph boundary set and under-reports that measurement for downstream planning.

**Fix:** Derive boundary records from the full graph using the same sink/barrier logic as `boundary_set/3`, and separately label any subset that matches explicit boundary exclusions.
