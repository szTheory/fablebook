## Critical Issues

### CR-01: [BLOCKER] Receipt verification accepts empty, self-consistent inventory evidence

**File:** `test/support/installed_otp.ex:236-249, 426-474`
**Issue:** `verify_receipt_lines!/1` only checks that the first and last records are `meta` and `footer`, that the footer counts match the number of parsed app/BEAM records, and that its digest matches the body. It does not require any app or BEAM records or validate the lock digest. Therefore a two-record receipt with exact lane/version labels, zero counts, and a recomputed body digest passes; `verify_receipt_files!/1` can accept one such receipt for each lane as a valid exact-lane receipt set. This makes the delivery gate unable to distinguish a complete inventory from an empty one.

**Fix:** Validate nonzero inventory counts, unique app and `{app,module}` records, and that each BEAM record belongs to a declared app with matching version/path. Verify `lock_sha256` against the approved lane lock digest from the validated source manifest before accepting either lane receipt.

## Warnings

### WR-01: [WARNING] Historical active-coverage test does not assert a historical lower bound

**File:** `test/contract/tier_sweep_test.exs:2047-2058, 2756-2777`
**Issue:** The new preservation test checks that current `exported` and `edges` are subsets of the current full graph. Those relations follow from constructing the active view by filtering that same full graph, so they still pass if active exports or edges disappear. `historical_active_modules` is also rebuilt from the current discovery result; it is not a captured pre-change module/export/edge set. This does not enforce Plan 01’s requirement to retain the former active graph as a lower bound.

**Fix:** Record the old active app/module/export/edge identities as an explicit baseline before changing graph discovery, then assert each baseline set remains present in the new active view (including the direction of edge inclusion that matches the former graph contract).
