### Pattern 1: Pin Sources Before Citing Behavior

**What:** Add exact core/floor parser and tokenizer members to the approved archive and extend the existing manifest/resolver identity records. Revalidate the archived `asn1ct.erl` caller hashes; cite only the resolver’s exact lane result.

**When to use:** Before source citations can support any behavior or disposition.

**Evidence contract:** `SweepEvidence.load_archive!/2` checks the archive digest, parses the archive, validates the manifest and extracts sources; `resolve!/2` checks the file digest and source-line bound. Archive paths reject duplicate entries, non-regular entries and unsafe paths. [VERIFIED: `test/support/sweep_evidence.ex:163-225`]

**Pitfall:** Updating archive bytes without updating all asserted archive-digest pins leaves stale evidence contracts. Search for dependent digest constants/assertions in the same task as the archive change.

### Pattern 2: Preserve the Original Row and Make Removal Consequences Individual

**What:** Recompute the live EX-107 full lane set, represent the selected four MFAs losslessly, preserve all other matches as pending, then establish the selected matcher’s disposition with exact lane evidence. If a matcher is removed, its own removal must expose a previously covered selected MFA on each applicable lane.

**When to use:** During integrated contract changes after source review, without converting this child slice into whole-row closure.

**Example:** The existing ASN.1 table contract asserts live match-set equality with the unchanged EX-107 lane set and current selected/pending partition, then resolves citations from archive-only evidence. Its specific existing counts are table-slice values only and must not be reused for this phase. [VERIFIED: `test/contract/tier_sweep_test.exs:10340-10415`]

### Pattern 3: Probe Static Guards Without Calling the Audited Function

**What:** Reuse existing source and compiled-BEAM probes, keeping dangerous operations in uncalled function bodies. The contract tests demonstrate detection; they do not exercise runtime atom creation.

**When to use:** Only for selected fronts whose source review supports a retained guard.

**Boundary:** `test/contract/banned_calls_test.exs` includes guard tiers and front declarations; the ASN.1 phase must derive any required entries from its own source trace, not copy based on function names. [VERIFIED: `test/contract/banned_calls_test.exs:13-80`]

## Common Pitfalls

### Treating names as semantic evidence

**What goes wrong:** `parse`, `file`, or `format_error` labels are used to retain/remove a ban without tracing behavior and input provenance.

**How to avoid:** Inspect each exact lane body, delegates, caller argument construction, and the full caller path. Do not infer a result from the adjacent table-wrapper phase.

### Reviewing only direct callers

**What goes wrong:** The four graph edges are checked while the wrapper or internal delegate path that supplies or transforms input is skipped.

**How to avoid:** Include the complete `asn1ct_parser2.erl` and `asn1ct_tok.erl` sources and the `set_scan_parse_pass/1` wrapper context; reconcile the four inventory edges separately on core and floor.

### Losing matches or witnesses during bounded extraction

**What goes wrong:** A selected slice silently caps or replaces the original EX-107 set, or a broad overlapping matcher makes a removal test vacuous.

**How to avoid:** Assert full live-vs-authoritative row equality per lane, exact selected membership and complement preservation. Removal controls must identify an individual relevant matcher and lane.

### Cross-lane source substitution

**What goes wrong:** Similar OTP versions are treated as byte-identical or source citations use one lane’s line numbers for the other.

**How to avoid:** Bind and cite each lane separately by exact ref, full SHA-256, byte count, and line span. Both target-file hashes differ across lanes.

### Accidentally executing an audited API

**What goes wrong:** A “fixed-input” probe invokes parser/tokenizer behavior and is mistaken for harmless static evidence.

**How to avoid:** Keep guard probes uncalled and inspect source/compiled artifacts only. Never run the audited functions or atom sink as part of this phase.
