## Architecture Patterns

### Evidence flow

Core/floor lane → InstalledOtp graph and receipt
Approved source archive → SweepEvidence source binding
Graph/receipt + source binding → selected-file audit and DebuggerSettings ownership/remainder receipt
Both lane assertions → required current-head CI → phase validation/delivery evidence

The existing helper connections are direct: InstalledOtp records lane identity, SweepEvidence checks archive and runtime, and DebuggerSettings compares graph identities to adopted ownership. [VERIFIED: test/support/installed_otp.ex:8-31; sweep_evidence.ex:14-43; debugger_settings.ex:2870-2904]

### Recommended project structure

Keep the contract in test/contract/tier_sweep_test.exs and evidence in this phase directory. Existing tests already hold the selected-file audit and both child receipt seams. [VERIFIED: tier_sweep_test.exs:5043-5052,5162-5218,5220-5254,5360-5366; CONTEXT.md:59-85]

### Pattern: one aggregate lane contract

Add a unique test tag to a small wrapper that combines the existing selected-file audit with adopted ownership and full remainder receipt assertions. Run it under each exact lane in the current PR CI. Retain source digest, receipt digest, lane and per-owner dispositions in the phase evidence; do not change ledger ownership or freeze historical counts. This is a recommendation, not existing behavior. [INFERRED from: tier_sweep_test.exs:5043-5052,5162-5218,5220-5254,5360-5366; CONTEXT.md:19-29]

### Minimal negative controls

Reuse existing cases; add only a cross-slice control if the aggregate wrapper creates a new omission seam. Useful controls are one omitted inherited family identity, a stale/wrong-lane source or receipt, and owner drift that must remain reported under .3 rather than be accepted by the child. Existing tests already test these failure classes. [VERIFIED: tier_sweep_test.exs:5380-5469,5484-5561,5162-5218,5220-5303; recommendation inferred from CONTEXT.md:27-29]

- Do not call the remainder-only verifier a wide gate; it accepts only "debugger-remainder". [VERIFIED: installed.py:117,2934-2935]
- Do not close/reassign parent .3 rows or claim runtime safety. [VERIFIED: CONTEXT.md:9-11,19-25]

## Common Pitfalls

1. **Treating historical parent completion as fresh.** The recorded completion uses old head 54cbe8aa2442a687b6fa9227d23b427258bbb1f3 and run 41190664671. Re-run live selected-file contract in both lanes; keep .3 rows with their owner. [VERIFIED: parent ledger decompressed rows 7458-7460,14767-14769; CONTEXT.md:9,22-25]
2. **Running the stale parent verifier as the current path.** It pins the base archive and missing Markdown; it will reject current candidate bytes. Use live SweepEvidence and the existing selected-file ExUnit contract for revalidation. [VERIFIED: ownership.py:332-338,608-677; sweep_evidence.ex:14-24]
3. **Calling a child scope the wide gate.** verify-scope supports only "debugger-remainder"; combine parent and both child owners in the live acceptance seam. [VERIFIED: installed.py:117,2821-2835,2934-2935; CONTEXT.md:19-25]
4. **Overclaiming security.** Static source/BEAM proof does not establish runtime safety; SEC-01 remains Phase 5. [VERIFIED: CONTEXT.md:9-11,22-25; REQUIREMENTS.md:365-370]
