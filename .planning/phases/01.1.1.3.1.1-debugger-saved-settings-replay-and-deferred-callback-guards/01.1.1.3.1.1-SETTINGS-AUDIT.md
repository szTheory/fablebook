## Negative controls and limits

The tagged audit rejects an empty record, an empty branch map, missing default/read-error branch identities, a missing function, wrong lane evidence, altered expected source text, a wrong source SHA, and an out-of-range line. The controls verify lane/MFA/owner/chain/remedy diagnostics. Function and export equality use both an independent installed BEAM scan and the existing graph; the three root identities must also match the effective ownership ledger and appear among fresh graph candidates.

The legacy tuple's literal `keep`, the current seven key names, and missing-key `proplists:get_value/2` behavior are recorded as source behavior only. Local `int:i/1` and global `int:ni/1` file restoration distinguish empty, one-file, and multiple-file inputs. Breakpoint status, enable/default action, custom action, tuple condition, and null condition remain separate branches. No inference is made about whether upstream code accepts missing or empty values.

This audit does not execute the debugger, GUI, serialized-term decoding, or caller-selected callbacks. It does not claim `init/3` is exported, complete the broad `dbg_wx_mon` module, or mark the module/root ownership complete. `dbg_wx_mon` and related wrappers/modules remain with their existing remainder owners; the whole-module `dbg_wx_mon` disposition is still pending under `01.1.1.3.1.2`.
