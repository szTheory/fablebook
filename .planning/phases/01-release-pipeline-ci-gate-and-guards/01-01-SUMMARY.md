## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Removed a module-level `require` from the message test**
- **Found during:** Task 3 (`mix ci`)
- **Issue:** Elixir 1.20.4 reported `warning: unused require Fablebook.Router` because the macro is only expanded through `Macro.expand_once/2` at runtime. That aborted `mix test --warnings-as-errors`.
- **Fix:** The test now builds its env with `Macro.Env.define_require(__ENV__, [], Fablebook.Router)`. This public API exists on 1.18 and 1.20, and the test still requires the router before expanding it.
- **Files modified:** test/contract/prod_guard_message_test.exs
- **Commit:** 670be01

**2. [Note] The Elixir 1.20 test summary line has a new format**
- The plan's `fails_when` looks for `1 test, 0 failures`. ExUnit on 1.20.4 prints `Result: 1 passed` instead, and exits 0. Elixir 1.18 still prints `1 test, 0 failures`, as the floor run shows. Treat the two as equivalent. Plan 01-02's CI checks should not grep for the old string on the latest lane.

**3. [Honesty rule, ADR 0010] SEC-02 and REL-01 not marked complete in REQUIREMENTS.md**
- `requirements.mark-complete SEC-02 REL-01` checked both boxes. I reverted that before committing.
- SEC-02 requires the **CI** prod build to assert the guard. That needs Plan 01-02's CI run link, and so far the only evidence is local.
- REL-01 requires 0.1.0 to be published, with a smoke test, a recovery workflow and an SBOM. That happens in Plans 01-02 to 01-05.
- Both requirements are advanced, not complete. Mark them complete when the CI run and the Hex publish provide the evidence.
