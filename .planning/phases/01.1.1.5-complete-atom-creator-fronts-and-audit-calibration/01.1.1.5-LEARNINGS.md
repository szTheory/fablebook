# Phase 01.1.1.5 Learnings: Complete atom-creator fronts and audit calibration

> Interim extraction after Plan 01 and the fresh-checkout cache repair. Refresh this file after the phase completes; later plans may change or add decisions and lessons.

## Decisions

### Reuse existing exact-lane contracts when they already prove the requirement
Plan 01 found the consult and Yecc records, source citations, guard tiers, compile-only probes, and omission controls already passed on both pinned lanes. No duplicate tests or guard changes were needed.

**Rationale:** Duplicating passing evidence adds maintenance without improving coverage.
**Source:** `01.1.1.5-01-SUMMARY.md`

---

### Keep one writable Hex cache home per checkout and seed it from local cache data
Keep cache mutation isolated under `_build/hex-home`; copy missing package and registry cache files from an existing local cache when available, without copying credentials, changing global Mix home, or replacing cache entries.

**Rationale:** The temporary checkout needed the existing cache while avoiding a shared writable Hex home and preserving `--check-locked`.
**Source:** `01.1.1.5-CACHE-RESEARCH.md`; `docs/research/ELIXIR-LANE-DX.md`

## Lessons

### A fresh isolated checkout may lack cache metadata even when the host is warm
The first setup failed to resolve `phoenix` while Hex registry requests timed out. Existing local package archives and registry records were enough for both lockfiles once copied into the checkout-local home.

**Context:** Successful `curl` requests did not establish that the Hex registry endpoint was responding to Mix; cached setup completed with timeout messages still present.
**Source:** `01.1.1.5-01-SUMMARY.md`; `01.1.1.5-CACHE-RESEARCH.md`; `docs/research/ELIXIR-LANE-DX.md`

---

### Keep cache recovery distinct from dependency resolution policy
Seed only cache data, then keep `mix deps.get --check-locked`; a stale cache must not silently rewrite the lockfile.

**Context:** Registry fallback helps an offline or slow setup only when the local records match the committed lock.
**Source:** `docs/research/ELIXIR-LANE-DX.md`; [Mix deps.get](https://mix.hexdocs.pm/1.20.4/Mix.Tasks.Deps.Get.html)

---

### State the next command and actor at every handoff
Record the current plan/wave, blocker or lack of blocker, exact command, checkout path, and who acts next in both chat and the durable continuation note.

**Context:** The previous handoff left the user unsure whether to clear context, find a checkout, or run a GSD command. This handoff names the exact isolated checkout and the next command.
**Source:** `INT-20261102-01`; `CLAUDE.md`; `.continue-here.md`

## Patterns

### Read-only source cache seeding into per-checkout mutable state
Copy only missing immutable package archives and registry cache records into an isolated checkout-local Hex home; omit `hex.config` and credentials.

**When to use:** A clean checkout has an isolated cache home, an existing trusted local cache is present, and the normal registry is unavailable or slow.
**Source:** `bin/lane`; `CONTRIBUTING.md`; `docs/research/ELIXIR-LANE-DX.md`

---

### Add Docker only for a demonstrated environment boundary
Compare cache and container patterns in neighboring projects, then choose the smallest approach that solves this repository's observed issue. Keep host-native pinned lanes for the single-library path; consider containers when service/native/OS parity or onboarding requires them.

**When to use:** Deciding whether to add a development container or Compose workflow.
**Source:** `docs/research/ELIXIR-LANE-DX.md`; `01.1.1.5-CACHE-RESEARCH.md`

## Surprises

### The floor lane completed while registry requests were still timing out
Cached registry records and archives were sufficient for locked dependency resolution and compilation.

**Impact:** Local cache fallback can unblock setup without claiming network health; keep timeout output visible and distinguish cache success from registry availability.
**Source:** `01.1.1.5-01-SUMMARY.md`; `docs/research/ELIXIR-LANE-DX.md`

---

### Sibling Docker patterns serve nested demos and toolchains, not Fablebook's ordinary library setup
The inspected repositories use persistent volumes where Docker owns an app/demo tree, toolchain container, or integration services. Fablebook's immediate failure was missing local Hex data in a host checkout.

**Impact:** A container would introduce another environment without addressing the smaller cache seeding issue.
**Source:** `docs/research/ELIXIR-LANE-DX.md`; `01.1.1.5-CACHE-RESEARCH.md`
