### `test/support/beam_walker.ex` (utility, transform)

**Analog:** itself. The module stays `@moduledoc false`, all helpers private, no comments.

**CR-04 site, plan 1** (lines 37-38, current):
```elixir
  defp function_code(forms),
    do: for({:function, _, name, _, _} = form <- forms, name != :__info__, do: form)
```
Target (RESEARCH Pattern 1, prototyped): bind `arity` and filter `{name, arity} != {:__info__, 1}`. `atoms/2` (lines 40-47) keeps walking all forms; only `pairs` and `literals` consume `code` (lines 16, 24-25).

**SC3 site, plan 3** (lines 56-59, current):
```elixir
  defp literals({:atom, _, atom}, acc), do: MapSet.put(acc, atom)
  defp literals(term, acc) when is_tuple(term), do: literals(Tuple.to_list(term), acc)
  defp literals(term, acc) when is_list(term), do: Enum.reduce(term, acc, &literals/2)
  defp literals(_term, acc), do: acc
```
Insert the three call-name clauses from RESEARCH Pattern 2 between the first and second clause (remote call: walk `module` and `args`, skip the function-name atom; local call: walk `args` only; remote `fun` capture: walk `module` and `arity`). Leave `pairs/2` (lines 49-54) untouched: pairs on call names are intended (`:c.nc(p)` gives the pair `{:c, :nc}`).

**Style constraint:** `mix ci` compiles `test/support` with `--warnings-as-errors` (`mix.exs:32` puts it in `elixirc_paths(:test)`) and runs `credo --strict` over it. 01.1-03 hit "Function body is nested too deep (max depth is 2, was 3)" here and fixed it by extracting `function_code/1` (01.1-03-SUMMARY line 172). Keep each new clause a one-liner.
