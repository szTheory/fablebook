## Summary

The guard has two static layers. The **BEAM layer** is `test/support/beam_walker.ex` plus `hits/1` in `test/contract/banned_calls_test.exs`. It reads each `lib/` beam's debug info and reports four families: atom-tier names anywhere, the imports chunk (direct remote calls), adjacent `{:atom, m}`, `{:atom, f}` pairs, and literal references to modules the MFA tier bans whole. The **source layer** is `credo/checks/banned_calls.ex`, which today matches only the 28 atom-tier names. Every gap in this phase maps to one of three code sites: the walker's function filter (CR-04), the walker's literal family (SC3), and the missing MFA-tier logic in the Credo check (VR-01, WR-11, WR-12). The rest is tier data, fixtures and the sweep.

I reproduced every starting number on both lanes. The existing sweep against the 45-entry tier prints `undisposed=152`. Against the 125-entry candidate tier (45 plus the 80 entries from `a3dab47`) it prints `undisposed=0` without deps (`reached=816 covered=395 excluded=421` on 1.20.4/OTP 29; `reached=794 covered=384 excluded=410` on 1.18.4/OTP 27.3.4.15). With the 12-app prod dependency closure added, it prints `undisposed=61` on **both** lanes, with identical rows (Phoenix 1.8.16/LV 1.2.13 latest, Phoenix 1.8.9/LV 1.2.9 floor). A full sweep run takes about 5 to 9 seconds of wall time, so it is cheap enough to run as a CI contract test on both lanes. I prototyped the CR-04 fix and the SC3 call-name narrowing in a scratch copy: the contract test stays green apart from the three strictness rows that are meant to change, and all CR-04 and SC3 probes behave as the success criteria require. I also prototyped the source-level check: every SC6 and WR-12 shape hits, `Regex.compile/1` does not, and `lib/` plus `mix.exs` stay clean.

Three findings change the plan's scope. First, the checker's false exclusion reasons are real. `Mix.Tasks.Format` evaluates a caller-chosen file through `Code.eval_file`. `Mix.Tasks.Help.run(["app:" <> app])` calls `String.to_atom(app)` and then `Mix.ensure_application!(app)`. `ExUnit.Diff.compute/3` calls `Code.eval_quoted` on caller AST. `Mix.Local.append_paths/0` adds `MIX_PATH` entries to the code path. Second, narrowing SC3 drops coverage of real atom-creating calls that are caught today only because they are named `compile`. A falsification probe confirmed atom creation from input for `Logger.Formatter.compile/1`, `EEx.Compiler.compile/3`, `Phoenix.Template.ExsEngine.compile/2`, `Phoenix.Template.EExEngine.compile/2`, `Phoenix.LiveView.Engine.compile/2` and `:xref_compiler.compile/2`. Each of these needs an explicit tier entry **before** the narrowing lands. Third, a reachability sweep cannot cover atom-creating parsers. Seeding it with the parser modules explodes to 5,555 undisposed rows. Parser coverage therefore has to be a disposition outside reachability, never a recorded limit (Open Question 1, resolved: Phase 01.1.1.1).

**Primary recommendation:** Five sequential contract-test-only PRs: (1) CR-04 walker arity fix; (2) the sweep as a committed both-lane contract test with deps, the audited exclusions and the swept tier; (3) SC3 narrowing with the `compile`-named tier entries added first; (4) the MFA-tier logic folded into the existing `Fablebook.Credo.BannedCalls`, including over `mix.exs` (VR-01, WR-11, WR-12); (5) the Credo explanation rewrite with the human wording check. Keep every tier and the exclusions in `test/contract/`, where D-21 protects them. Mirror the MFA tier into the Credo check behind an equality assertion, exactly as the atom tier is mirrored today.

### Pattern 1: CR-04, skip only the generated `__info__/1`
**What:** The walker drops every `__info__` arity, but Elixir reserves only arity 1.
**Current code** [VERIFIED: test/support/beam_walker.ex:37-38]:
```elixir
  defp function_code(forms),
    do: for({:function, _, name, _, _} = form <- forms, name != :__info__, do: form)
```
**Fix** (prototyped this session; the contract test stayed green apart from the planned strictness rows):
```elixir
  defp function_code(forms),
    do: for({:function, _, name, arity, _} = form <- forms, {name, arity} != {:__info__, 1}, do: form)
```
Measured with the narrowed walker (latest lane, scratch copy): `__info__/2` with `apply(:erlang, :load_module, [m | args])` hits `[mfa: {:erlang, :load_module, :_}]`; `apply(Module, :concat, parts)` hits `[mfa: {Module, :concat, :_}]`; `Function.capture(:file, :script, n).(p)` hits `[mfa: {:file, :script, :_}]`; a `def __info__` of arity 0 also hits [VERIFIED: local probe, Elixir 1.20.4/OTP 29.1.1]. One fixture per probe is required. `@fixtures` generates test names from the file's root name, so three entries for one file would collide. Name them, for example, `info_load_module.ex`, `info_concat.ex` and `info_capture_script.ex`, each defining a public `__info__/2`, all listed in `@beam_only_fixtures`. Also align the sweep's own `n != :__info__` filter, for consistency.

### Pattern 2: SC3, narrow the whole-module literal family to non-call-name positions
**What:** `literals/2` today collects every `{:atom, _, a}` in function code, so the function-name slot of a remote call (`Regex.compile`), a local call (`compile(x)`) and a remote capture (`&Regex.compile/1`) all count [VERIFIED: test/support/beam_walker.ex:56-59; banned_calls_test.exs:477 `literal_hits = for m <- literals, {m, :_, :_} in @mfa_tier, do: {:mfa, {m, :_, :_}}`].
**Abstract-code shapes** [VERIFIED: local probe, both shapes printed from debug info]:
- `Regex.compile(s)` → `{:call, _, {:remote, _, {:atom, _, Regex}, {:atom, _, :compile}}, args}`
- local `compile(s)` → `{:call, _, {:atom, _, :compile}, args}`
- `&Regex.compile/1` → `{:fun, _, {:function, {:atom, _, Regex}, {:atom, _, :compile}, {:integer, _, 1}}}`
- `apply(:compile, f, a)` → `{:call, _, {:remote, _, {:atom, _, :erlang}, {:atom, _, :apply}}, [{:atom, _, :compile}, ...]}` (argument position, so it must still hit)
**Fix** (prototyped):
```elixir
  defp literals({:atom, _, atom}, acc), do: MapSet.put(acc, atom)

  defp literals({:call, _, {:remote, _, module, {:atom, _, _}}, args}, acc),
    do: literals(args, literals(module, acc))

  defp literals({:call, _, {:atom, _, _}, args}, acc), do: literals(args, acc)

  defp literals({:fun, _, {:function, module, {:atom, _, _}, arity}}, acc),
    do: literals(arity, literals(module, acc))

  defp literals(term, acc) when is_tuple(term), do: literals(Tuple.to_list(term), acc)
  defp literals(term, acc) when is_list(term), do: Enum.reduce(term, acc, &literals/2)
  defp literals(_term, acc), do: acc
```
Measured after the change: `Regex.compile/1`, `:re.compile/2`, a local `compile/1` and `&Regex.compile/1` give `[]`. `apply(:compile, f, a)` gives `[mfa: {:compile, :_, :_}]`. `&:compile.file/1` gives `[mfa: {:compile, :_, :_}, mfa: {:compile, :file, :_}]`. Every existing fixture still hits, including `computed_compile.ex`. The only failure is the strictness test, at the three rows SC3 changes [VERIFIED: local probe; contract test `38/39 passed`, the one failure being `Fablebook.GuardFixture.StrictRegex: []`]. Keyword and data rows (`[epp: 1]`, `[compile: true]`, `[io: :read]`) are unchanged, because they are not call names.

### Pattern 4: the source-level MFA check, inside the existing Credo check
**What:** Extend `Fablebook.Credo.BannedCalls`. Do not add a second check: adding one would mean editing `.credo.exs` and the `@ban_checks` list. Mirror the walker's rules at source level, over the whole file, including module bodies and `quote` blocks.
**AST shapes** [VERIFIED: local `Code.string_to_quoted!` probe]:
- quoted call: `quote(do: Module.concat(unquote(x)))` → `{:quote, _, [[do: {{:., _, [{:__aliases__, _, [:Module]}, :concat]}, _, [...]}]]}`
- alias: `alias Module, as: M` → `{:alias, _, [{:__aliases__, _, [:Module]}, [as: {:__aliases__, _, [:M]}]]}`; `alias :file, as: F` → `{:alias, _, [:file, [as: ...]]}`; multi-alias `alias Foo.{Bar, Baz}` → `{:alias, _, [{{:., _, [{:__aliases__, _, [:Foo]}, :{}]}, _, [...]}]}`
- newline after the dot: `Module.\nconcat([x])` parses to the same remote call
- `apply(Module, :concat, [x])` → `{:apply, _, [{:__aliases__, _, [:Module]}, :concat, [...]]}`
- `x |> Module.concat()` has an argument list one shorter (so match `{m, f}` regardless of arity, as the walker's pair family does)
- `Elixir.Module.concat(x)` → aliases head is the atom `Elixir`; `:"Elixir.Module".concat(x)` → a plain atom `Module`
- `%{:erlang => :load_module}` → `{:%{}, _, [erlang: :load_module]}`; `{:erlang, :load_module, a}` → `{:{}, _, [:erlang, :load_module, a]}`
- `Macro.prewalk` calls the visitor on list literals and 2-tuples, but **not** on a call's argument list as a whole. Check adjacency on `{form, meta, args}` argument lists explicitly, and skip the `{:., _, [m, f]}` dot node so that call names are never treated as data (SC3 at source level).
**Rules:**
1. A remote call `{{:., _, [mod, fun]}, _, args}` where the alias-expanded `mod` is banned whole, or `{mod, fun}` matches a tier entry (ignore arity).
2. Adjacent literals in any argument list, list literal or 2-tuple: a module literal followed by an atom matching a tier pair.
3. A whole-module literal in a non-call-name position.
4. Atom-tier names anywhere (today's behaviour, unchanged).
5. Imports: `import M` followed by a local call `f(...)` with `{M, f}` in the tier. Recommended conservative form: flag the `import` of any module that has a tier entry. `lib/` imports only `Plug.Conn` today.
Compare names as **strings** (`"Module"`, `":file"`) built from AST parts. That way the check itself never calls `Module.concat` on source-derived names.
**Prototype result** (strings-based, a 6-entry tier): every SC6 and WR-12 probe hit, including the quoted `apply(:erlang, :load_module, ...)` and the `@r apply(:file, :script, ...)` pair. `Regex.compile(s)` gave `[]`, and `apply(:compile, f, a)` and `[compile: true]` hit as whole-module literals. `lib/fablebook.ex`, `lib/fablebook/placeholder.ex`, `lib/fablebook/router.ex` and `mix.exs` gave `[]` [VERIFIED: local prototype run]. The executor must re-run this with the full tier.

### Pattern 6: generated per-entry live probes (SC2, "every entry is proven live")
For each `@mfa_tier` entry, generate one probe module in `tmp_dir`. Use the existing strictness-table pattern: write source, then `compile!`, then `BeamWalker.scan`.
- `{m, f, a}` → `def run(...), do: m.f(...)` at arity `a`;
- `{m, f, :_}` → one direct call per exported arity of `f`;
- `{m, :_, :_}` → one call to some exported function, and expect the literal hit `{:mfa, {m, :_, :_}}`.
Skip `MACRO-*`, `__info__` and `module_info`. Assert `{:mfa, {m, f, a}}` in `hits(scan)`. The fixture compile helper already captures warnings and accepts deprecation and undefined-module warnings. ### Anti-Patterns to Avoid
- **Whole-module entries for ordinary-word modules** (`:c`, `:make`, `:cover`, `:shell`, `:escript`, `:code`, `:elixir`, `:file`, `:io`, `Mix`, `Mix.Project`, `Code`, `Record`). The literal family would flag keyword keys and option values (`fit: :cover`, `app: :elixir`). Use function entries. `Fablebook.Router` calls `Mix.env/0` and `Mix.Project.config/0`.
- **Module-level exclusions that hide a front door.** The checker's false reasons came from whole-module exclusions (`{Mix.Tasks.Format, project_build}`, `{ExUnit.Diff, own_clauses}`). Where a module mixes front doors and internals, exclude by function.
- **Parsing the test file with `Code.eval_quoted` to read the tier.** Use the mirror.
- **Narrowing before the tier entries land.** SC3 says "first". Keep both in one PR, with the entries committed first.
- **Treating `@beam_only_fixtures` as "Credo cannot flag".** It means "Credo is not required to flag". After plan 4 most beam-only fixtures will also raise a Credo issue. Add a symmetric `@source_only_fixtures` list (expected Credo issue, walker pinned at `[]`) for the macro and module-body fixtures.
- **Lowering a gate to pass:** editing `@allowlist`, removing a tier entry, narrowing sweep scope, sinks or seeds, or excluding with a reason that the source does not support.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Static call graph over thousands of beams | A custom edge extractor over every form | `:xref` `functions` mode (`q("E")`, `q("X")`) plus the existing literal-pair edge pass | xref handles exports, local and remote calls and builtins. The pair pass adds only literal dispatch |
| Reading the abstract code of a beam | Parsing `.erl`/`.ex` source | `:beam_lib.chunks(path, [:debug_info])` + `backend.debug_info(:erlang_v1, mod, data, [])` | Already the walker's path. It works for Elixir and Erlang beams |
| Source AST traversal in Credo | A hand-written recursive descent | `Credo.Code.prewalk/3` (`Macro.prewalk`) | Already used by the check |
| Deciding whether a function creates atoms | Reading source alone | Falsification probe: call it with a fresh name, then `:erlang.binary_to_existing_atom/1` (or the `system_info(:atom_count)` delta) | Turns a judgment into a reproducible observation. Use a control such as `Regex.compile/1` |
| Prod dependency closure | A hardcoded app list | The `hex_metadata.config` walk already in `dependency_budget_test.exs` | Stays right when a dep adds a runtime dependency |

**Key insight:** in this domain, a static guard is only as true as its tier data. Derive the tier from the code path (the sweep), prove each entry live (generated probes plus the existence test), and pin every miss as a strictness row. Never trust a hand-picked list.

## Common Pitfalls

### Pitfall 1: The sweep cannot cover atom-creating parsers
**What goes wrong:** Seeding the reverse walk with parser modules marks nearly the whole code path as reached.
**Measured:** with the parse-only tier entries as seeds, `reached=7919 ... undisposed=6137`. With only `:erl_scan`, `:erl_parse`, `:elixir_tokenizer`, `:elixir_parser`, `:epp`, `:epp_dodger`, `:xmerl_scan`, `:elixir.string_to_tokens` and `:elixir.tokens_to_quoted` as seeds: `reached=7287 ... undisposed=5555` [VERIFIED: local run, 1.20.4/OTP 29.1.1, deps included].
