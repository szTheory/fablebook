## Implementation Decisions

The owner requested all relevant decision areas be researched with subagents and a coherent recommendation set adopted automatically (INT-20261029-10, reaffirming INT-20261028-17). Three advisers covered atom semantics/security, OTP coverage/CI, and exclusion audit/DX/delivery; a further adversarial reconciliation checked overlap, lane drift, source availability and false-green coverage. These are adopted discussion decisions, not owner answers to individually presented questions. Existing intent and ADRs remain controlling. Unrated decisions are reversible.

### Atom policy and guard behavior

- **D-01: Judge caller influence and behavior, not function names.** Follow public front doors through wrappers to atom-producing or evaluator/loader behavior. A function returning ordinary data can still intern atoms. Names such as `parse`, `compile` or `to_atom` are discovery aids, not a completeness proof. Keep a source-backed disposition and negative guard fixture for each newly banned front door. Use the existing sweep and boundary contracts; do not build a general-purpose taint-analysis framework.
- **D-02: Separate provenance without weakening existing bans.** Distinguish caller-chosen text/files/pathnames that can create atoms, existing-atom lookup, and compile-time AST/macro expansion. Existing-atom lookup is not new-atom creation, but this phase does not remove its existing conservative ban or declare it safe for input-controlled dispatch. Source-to-sink analysis must cover parsers currently filtered out of evaluator reachability. Explicitly dispose of `:file.path_consult/2`, `:yecc.file/2`, `:yecc.yecc/2..4` where exported, and `Logger.Formatter.new/1` with caller `format:`. StrictPathConsult must report hits; safe-argument branches do not justify a blanket exclusion for an unsafe public function.
- **D-03: Prove detection without executing the dangerous operation.** Reuse the mirrored Credo and compiled-BEAM tiers, hand-written fixtures, generated per-entry probes, source-only dispatch fixtures and known-strictness rows. New fixtures keep dangerous calls in unexecuted function bodies; compiling and inspecting them proves detection, not runtime atom behavior. Keep direct/capture/apply and relevant source-only dispatch coverage. Preserve benign controls such as regex compilation and the accepted static-analysis limitations; never claim a complete runtime proof from a static guard.

### Installed OTP coverage

- **D-04: Discover the installation independently on each lane.** Cover every installed OTP application under the lane's OTP installation, even when Mix has pruned it from the active code path or the application has not been started. Retain Elixir app coverage and the production dependency closure derived from `mix.exs`. Use discovered installed-app/BEAM sets as the authority; a frozen 17/18-app count, loaded-app list or hand-maintained filter cannot define scope. Include debugger remainder and Common Test front doors when installed; StrictCtMake must report hits. Record each lane's actual inventory and versions as evidence.
- **D-05: Make missing coverage observable and fatal.** Assert installed-app versus swept-app equality, no out-of-scope installed app, and coverage of the discovered BEAM inventory. Check xref ingestion results and preserve the no-debug-info failure; unreadable files, ignored scan failures or missing source analysis are not empty results. Add a nonvacuous inventory control that omits a discovered app or introduces a synthetic installation entry and demonstrates failure, alongside existing tier-removal and boundary controls. Never start GUI/debugger apps or invoke their evaluator/loader APIs merely to inspect them.

### Exclusion truth and evidence

- **D-06: Require substantive triples.** Every carried exclusion is `{matcher, reason_key, citation}` with a known reason and nonempty app-relative source citations. Reject two-tuples, empty citation collections, malformed paths, nonexistent source locations and unsupported lane claims. Function-level matchers are the default. A module/prefix matcher is retained only when its reason demonstrably covers every matched function on both lanes; a label such as `pure_data`, `callback`, `macro` or `expansion` is not evidence on its own.
- **D-07: Audit the caller-argument rule entry by entry.** Keep a durable audit table mapping every ported entry to its matched functions, caller-input trace, verdict, replacement or retention, and exact-lane citations. A false reason becomes explicit tier entries with fixtures or narrower source-backed exclusions. Source review establishes the semantic verdict; executable checks establish record validity, citation resolution and complete row/disposition coverage. Do not add owner UAT for every table row or claim that a citation regex proves semantic truth.
- **D-08: Prove each retained exclusion is necessary.** Removing each audited exclusion in memory must leave at least one previously covered row undisposed on each lane where the exclusion applies. Narrow, merge or remove overlapping/redundant matchers rather than accepting vacuous controls. A lane-absent function/app needs explicit inventory/export evidence for absence, not a fabricated citation or silent skip. Preserve every source-audited disposition; removal controls do not replace semantic review.
- **D-09: Match source evidence to the exact toolchains.** Research must establish source availability and citation resolution for the actual CI lanes before planning the automated citation checks. At discussion time, `.tool-versions` selects Elixir 1.20.4/OTP 29.1.2 and `.github/actions/setup/action.yml` selects floor Elixir 1.18.5/OTP 27.3.4.9. Prior local receipts using OTP 29.1.1/27.3.4.15 are historical, not current-lane citation proof. Prefer matching installed/already-provisioned source; add no network fetch to recurring tests. If matching sources are unavailable, report that prerequisite as unavailable and propose a compliant resolution during research; manual review alone cannot be relabelled as an automated source-resolution pass. Preserve the roadmap's both-lane cited-reason gate.

### Collisions, explanation and delivery

- **D-10: Investigate the AST boundary before classifying Macro.expand.** `lib/fablebook/router.ex:35` already calls `Macro.expand(book, caller_env)` while expanding the router macro. Official semantics include alias expansion to atoms and macro expansion, but this is caller AST at compile time; the discussion has not established a violation of the narrower caller-text/file rule. Its semantic disposition and atom provenance are an explicit research prerequisite. Do not presume that the current blanket `:expansion` exclusion survives the audit.
- **D-11: Preserve the library-collision hard stop.** If any newly judged front door is already called from `lib/`, stop that implementation and report the exact MFA, call site, caller-input trace and triggering guard. Do not weaken the ban, silently add an exclusion, or select an allowlist/refactor remedy here. ROADMAP SC4 requires an owner-recorded decision for an ADR-backed allowlist entry or a separate `lib/` PR. Unrelated work can proceed only when independent and without claiming phase closure. Generic auto-follow authority does not waive this gate.
- **D-12: Make the explanation truthful and review only changed wording.** Remove the two transferred-open-item paragraphs only after their guarantees are implemented. Map every changed claim to a fixture, strictness row or sweep/boundary assertion. Retain the accepted computed-dispatch and write-then-load limitations and the Phase 5 backstop. Record the required human wording check before merging the changed explanation. Existing approval covers unchanged wording; this discussion does not supply the future wording approval.
- **D-13: Reuse the existing small delivery and CI model.** Sequential scoped PRs remain contract-test-only: no `lib/`, `.github/`, `mix.exs`, lockfile or `.credo.exs` changes bundled with the guard work. Reuse core/floor, the existing strict Credo/mix CI gate and fixture infrastructure. Each implementation PR needs all checks passing under the existing allowed-skip rule, merge to main and a CI run link at the tested revision; local results stay labelled local. Preserve the five-plan cap and review cap; split substantive work if needed, never lower a gate. Batch bookkeeping with useful pushes and keep final run receipts in PR metadata when appropriate.
- **D-14: Research first, then stop at each GSD boundary.** The next command is plan-phase with `--research`. This adviser work informs the context; it does not substitute for the full phase RESEARCH.md or exhaustive API/exclusion enumeration. Keep GSD auto-advance disabled (INT-20261029-05). Add no dependency; use existing Elixir/OTP/ExUnit tools and small local helpers. Source resolution, exact helper layout, performance improvements and plan decomposition belong to research/planning within these decisions.
