## Tagged entry and publication contract

Create all record checks with both `:guard_aggregate_reconciliation` and `:guard_aggregate_reconciliation_records`; report/bundle checks carry both the aggregate tag and `:guard_aggregate_reconciliation_bundle`. The aggregate selector runs the whole slice, while the records selector can regenerate only machine records during accepted fixes. `FABLEBOOK_GUARD_AGGREGATE_WRITE=1` explicitly permits affected-lane record writes; when running the records sub-tag it never writes the report. `FABLEBOOK_GUARD_AGGREGATE_REPORT_WRITE=1` permits only report publication from an already validated same-generation core/floor/sizing bundle. Ordinary checks write neither. When collecting the first lane of a new bundle, defer cross-lane publication until the counterpart exists with matching generation/input identities; never overwrite a good report with a partial bundle. Assert a nonzero selected aggregate/records/bundle test count in the captured ExUnit results. Do not rely on a zero-test exit status.
