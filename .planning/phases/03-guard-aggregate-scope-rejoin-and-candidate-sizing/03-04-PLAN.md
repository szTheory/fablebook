The reviewer must be independent of the implementation author and receives the scope, locked decisions, exact artifact identities and required checks. Use the existing approved code/security review workflow when available; no new review framework or external service.

Retain the five-exact-source-file cap independently for every task, including rereads. Preserve the fixed 31,000-token reserve and use a 67,000-token working envelope: compact required context ≤38,000; Task 03-04-01 complete review spans ≤21,000; Task 03-04-02 correction/reread spans ≤1,000; Task 03-04-03 new source-body reads = 0; output ≤5,000; cushion ≤2,000. Prepare exact complete-span schedules with path/hash, function or record key, inclusive boundaries, bytes and span hash. Include the omitted identity-construction helper in Task 1's schedule if it fits within the 21,000-token total and five-file cap; otherwise preserve a precise owner-facing gap, consequence, and remedy without claiming complete identity review. Obtain independent schedule review, fresh execute preflight, and direct combined count including required context, schedule/review receipts, spans, output, cushion and reserve before emitting any source body. Effort allocation remains 3–4 hours for independent review, one correction/retest pass and report publication; record actual intervals and stop before bound violations.
