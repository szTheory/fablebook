## Common Pitfalls

### Treating zero pending MFA rows as a safety verdict

The two named debugger seed modules have inspected function/source records but no pending-MFA entries. That is a graph-membership observation, not source review or safety evidence; D1113-02 expressly says this absence is not a verdict. [VERIFIED: receipts in `01.1.1.3-CALIBRATION.md`; CONTEXT D1113-02]

### Treating an installed source file as resolvable exact-lane evidence

The offline resolver still requires a lane/source-path manifest row before it selects installed or archived source. This did not prevent this bounded read-only research: exact-tag source files were fetched to `/tmp`, checked against each lane's receipt byte count, and fingerprinted in the ownership artifact. Do not treat those temporary files as a recurring test fixture; resolver-backed tests need the separately approved source-map/fixture work. [VERIFIED: `test/support/sweep_evidence.ex:218-244`; exact-tag URL, size and digest rows in `01.1.1.3-OWNERSHIP.jsonl.gz`]

### Equating receipt counts or graph membership with completed review

`active_app` includes a mixed graph domain and cannot establish OTP semantic completion. Compare typed identity sets and explicit dispositions. Preserve pending ownership until reviewed, and do not let a family selector pass the global final gate. [VERIFIED: CONTEXT D1113-09/11; `test/support/installed_otp.ex:600-652`]

### Splitting caller chains at app or mechanism boundaries

Shared source/sink nodes and cross-app wrappers can produce chain overlap. Keep all chain relations while assigning each canonical item once. Receipt analysis found shared MFA nodes across chains, so a naive one-chain/one-disjoint-app partition would drop evidence or duplicate ownership. [VERIFIED: `01.1.1.3-CALIBRATION.md`; CONTEXT D1113-01/03]

### Calling dangerous test bodies

Fixtures should be compiled/inspected but never invoke evaluator, loader, GUI, debugger, Common Test, or caller-selected code. Static guard success does not prove runtime atom safety or all computed dispatch. [VERIFIED: CONTEXT D1113-08; `.planning/REQUIREMENTS.md:161`]
