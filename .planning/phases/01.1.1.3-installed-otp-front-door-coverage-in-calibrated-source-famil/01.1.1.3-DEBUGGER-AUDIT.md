# Debugger Source Audit

## Scope and verdict

This audit covers every function discovered in the exact installed BEAMs for `dbg_idb`, `dbg_istk`, and `dbg_wx_interpret`, plus those modules' full exports, reached functions, explicit source roots, tier roots, and exclusion roots. The discovered set agrees with the exact-lane source records. The observed count is 29 functions per lane; the guard compares identities dynamically and does not use 29 as an acceptance cap.

Two caller-input fronts have exact guard tiers: `dbg_wx_interpret:start/4` accepts user-selected file names and a directory and forwards them to the interpreter; `dbg_istk:from_external/1` accepts a caller-supplied stack binary and passes it to `binary_to_term/1` without validation or a safe option. The selected file filter does not constrain the public decoder. The paired `delayed_to_external/0` producer and `dbg_ieval` consumers describe observed internal provenance only.

## Fixed GUI provenance and ownership

The displayed module list starts with `int:interpreted()` in `dbg_wx_mon:init_contents/4`; `dbg_wx_mon_win` displays those existing module atoms with `atom_to_list/1`. The three auto-attach checkbox labels are fixed source strings: `First Call`, `On Break`, and `On Exit`. The callback later converts selected labels with `list_to_atom/1`.

These are provenance observations only. `dbg_wx_mon_win:handle_event/2` also accepts synthetic command events and keyboard paths, including `cmdString` and key-derived input. Its complete module/root disposition remains with Plan 01.1.1.3.1; this audit does not claim the callback globally safe. `dbg_iload`, `dbg_ieval`, the dialog getters, monitor menu, and error dialog are cited only at the paths above. Their remaining whole-module source work stays with their assigned owners.

The assigned three modules are included in active membership while historical members and `ct_make` remain present. The exact changed-family exclusion match set is empty on both lanes, so there are no debugger exclusion identities to replace and no exclusion removal witness to claim. Any future overlapping exclusion fails the checked match-set control.

## Limits

The fixtures compile and inspect direct calls, remote captures, `apply/3`, source-only quotes, and uninvoked macro bodies without invoking the debugger, decoder, GUI, or caller-selected data. Static guard evidence does not execute arbitrary bytes, prove runtime atom limits, or complete installed-OTP semantics. SEC-01 remains Pending for Phase 5.
