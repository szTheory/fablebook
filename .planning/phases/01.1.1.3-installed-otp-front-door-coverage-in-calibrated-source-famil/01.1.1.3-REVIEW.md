## Narrative Findings (AI reviewer)

### CR-01: BLOCKER — Pending module scope and owner are not independently pinned

**File:** `test/contract/tier_sweep_test.exs:555-562, 5580-5586`  
**Also affects:** `.planning/phases/01.1.1.3-installed-otp-front-door-coverage-in-calibrated-source-famil/01.1.1.3-DEBUGGER-AUDIT.md:80`

**Issue:** `assert_debugger_active_scope!/3` defines `pending` from `Map.keys(@debugger_pending_module_owners)`. The same map therefore supplies both the expected module set and the owner strings used only when formatting a failure. If an entry such as `:dbg_ieval` is removed, the guard no longer checks whether it became active or disappeared from the pending inventory. If its owner string changes, no assertion detects the changed assignment. This contradicts the documented promise that all six support modules remain pending under Plan 01.1.1.3.1 and leaves a path for an unreviewed family to fall outside the guard.

**Fix:** Pin the expected pending-module set independently from the owner map and assert exact set equality. Also compare module owners against a separate approved ownership source or pinned expected mapping, and add negative controls showing that removing a pending module entry or changing its owner fails. Keep the diagnostic owner display derived from the verified mapping.
